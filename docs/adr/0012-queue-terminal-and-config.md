# ADR 0012: durable prompt queue, terminal client and config restrictions

Date: 2026-10-09. Status: implemented engineering slice; full D/privacy acceptance pending.

Prompt queue entries are bounded immutable task blobs, referenced by typed journal metadata. Enqueue/remove never change spec, candidate, policy or the input barrier. Activation supplies the exact queued bytes and removes that entry in the same InputRecorded transaction that installs the steering barrier. Command payload conflicts, missing/corrupt queued bytes and stale activation fail closed. Historical queued payloads remain pinned by backup and orphan GC. Queue removal is not privacy deletion.

Kernel publication may retry a stale task cursor only when canonical authoritative state, excluding sequence and queue metadata, is unchanged. It cannot cross a steering barrier, spec/candidate/policy/resource mutation or owner generation change. This permits enqueue during inference without silently losing queue state or forcing a duplicate inference.

The TUI connects to the background owner through peer-authenticated IPC. It never writes SQLite directly. It uses existing control, observation, request/response, continuity and revision APIs. Exiting/crashing the UI does not own or cancel detached work. Raw prompts trigger steering; queue activation is explicit; revision and resume are explicit. Fixture revisions require a fresh fixture file. Approval is scoped to the exact current request and does not auto-resume.

Windows console and Linux/macOS terminal modes support a bounded Unicode composer, history, arrows, bracketed paste, resize polling and current state. Paste newlines/control bytes cannot dispatch commands. Renderer quotes source, logs and error strings; only client-owned terminal sequences are emitted. Line mode is available for redirected/accessibility use. Candidate file mentions resolve bounded fuzzy matches and require an exact path when ambiguous. Source references carry candidate/blob digest. Source page reads have bounded exact bytes; they do not read a newly changed live file.

First Ctrl+C requests pause; a subsequent settled interrupt requests cancel. This is not an accepted hostile process-tree force-stop protocol. Current durable state is polled; provider text deltas are not advertised as lossless replay. Shell/restore/graph/eval commands are not exposed as working capabilities while their required backends are absent. Full native terminal/PTY and platform acceptance remains necessary.

Secret-free config resolution separates preferences from restrictions. User then project preferences apply before explicit CLI fields. A repository cannot grant remote inference: the operator must still explicitly enable the selected runtime, and every retained restriction must admit it. Provider restriction null/absent means no added restriction; an explicit empty array means deny every provider and survives canonical serialization/restore. Privacy fields are independent restrictions; absent embedding/reranker/tool/telemetry/training/cross-project services remain disabled even if a preference file says true.

Global user config is outside source; project config is viber.config.json and its raw contents are excluded from capture. Sensitive paths are unioned and filtered before source bytes enter CAS. Policy also denies later reads/listing/proposal writes to those scopes. Their spellings are omitted from model policy instructions. Git capture fails closed when required Git/ignore metadata is explicitly denied; directory capture is the supported alternative. Existing tasks retain their admitted configuration; changing a file does not secretly rewrite a task policy.

Pending work is concrete: administrative hard-deny/current-policy revisions, retention and complete privacy deletion, generic export review/filtering, pinned sandboxed extension/MCP execution, full TUI task queue scheduling/force-stop/stream transport and platform acceptance. These are keyless requirements, not remote API-key acceptance.
