# ADR 0018: Transient restore operation lease yaşam döngüsü

10 Ekim 2026. Transient operation lease, persistent owner scope ve process fence aynı retention nesnesi değildir. Restore admission eski implementation'da her denemede yeni boş `.lock` bırakıyor, normal close/crash sonrasında katalog kapasitesini geri vermiyordu. Provenance taşımayan historical empty lock'lar otomatik benimsenmez.

Yeni operation lease ilk restore payload byte'ından önce family lock altında canonical `RESTORE_OPERATION` descriptor olarak no-replace publish edilir. Descriptor version, exact owner catalog pathname ve current genesis authority digest taşır. Native `LockExisting` regular/single-link/current inode'u doğrular; missing dosya yaratmaz. Persistent scope'nun instance ID'si aynı lease'e bağlıysa retirement reddedilir.

Normal close family lock alır, kendi native lease handle'ını kapatır ve yalnız kendi typed lease'ini exact inode/digest unlink + parent sync ile kaldırır. Bu sıra Windows'un open handle unlink sınırını karşılar. Yeni owner ve restore aynı family admission lock'a bağlıdır; eski lease pathname'i yeni operation için yeniden kullanılmaz. Cleanup hatası restore return error'a dahil edilir. Kullanıcı restore publication gerçekleşmiş olabileceği için mevcut destination'ı inceler; kör tekrar yapılmaz.

Abrupt process death descriptor publication/native lease acquire/lease release sınırında olursa mevcut private root'ta inactive typed file kalır. Sonraki restore veya explicit `privacy-capacity --retire-operation-leases` bunu geri alabilir. Preflight bütün bounded inactive inventory'yi denetler; first unlink öncesinde foreign/noncanonical/wrong genesis/oversized/scope-bound/hardlinked dosya varsa durur. Active lock'lar ve untyped historical lease'ler tutulur. Envanter ve removal arasında family lock bırakılmaz; removal öncesinde native liveness, inode ve bytes tekrar doğrulanır. Aynı anda yalnız bir probe handle açılır; 8192 katalog sınırı OS descriptor limitine çevrilmez. Kernel journal, registry sequence/tail/watermark, managed copy/attempt pins, task content, UNKNOWN ledger ve Docker name fence'leri değiştirilmez.

CLI/owner/TUI aynı store-scoped null-payload command'a bağlıdır. Missing store yaratılmaz; task ID, unsupported prune ve iki remediation flag'ini birlikte kullanma reddedilir. Status `RETIRE_INACTIVE_OPERATION_LEASES` eylemini sunar; kalan persistent/untyped katalog veya full journal yanlış work-ready olmaz.

Kabul gerçek child exit83 (üç boundary), active child/native lock, 10 retry, 7680 actual catalog entry, foreign inventory first-mutation denial, wrong authority/scope/hardlink/noncanonical/oversized/invalid ID ve identical-byte replacement inode reddini kapsar. Ayrı 512-file actual child Unix'te yalnız kendi `RLIMIT_NOFILE` soft limitini 64'e indirir; Windows aynı inventory'yi çalıştırır, Unix descriptor ceiling kanıtı Windows'a genellenmez. Named descriptor publication öncesindeki interrupted `.publish-*` orphan ve historical empty lock recovery bu ADR'nin cleanup yetkisi değildir.

Bu uygulama [ADR 0017](0017-privacy-checkpoint-design.md)'nin checkpoint/retention/multi-owner format migration veya persistent owner retirement tasarımını uygulanmış saymaz. Generic owner prune ve process fence expiry hâlâ ayrı provenance/effect kabulü ister.

Tam Windows suite owner-stop discovery yarışını ortaya çıkardı: shutdown reader açıkken unlink edilen descriptor inode'unun link sayısı sıfır olabilir. Native single-link primitive sıfır link için `os.ErrNotExist` döndürür; gerçek iki-link dosyası halen reddedilir. IPC discovery'nin mevcut no-owner yolu bunu kullanır; shutdown tamamlanması ayrıca gerçek store owner lock'unun alınmasıyla kanıtlanır. Yeni endpoint veya ikinci writer yetkisi yalnız pathname yokluğundan çıkarılmaz. Native held-reader unlink, fresh replacement namespace ve repeated supervisor start/attach/stop kabulü bu davranışı ayrı ölçer.
