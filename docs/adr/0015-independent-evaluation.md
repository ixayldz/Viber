# ADR 0015 — Independent candidate observation and paired accounting

Status: Accepted for the 0.9 engineering slice; full C10 and release gates remain open.

Imported benchmark rows are untrusted measurements. Integer-only CanonicalV1 binds the protocol, conditions, assignments, rows and manifest; float statistics are derived presentation JSON bytes. Reports preserve every fixed assignment, failed retry cost, missing run, safe-handling cohort and unknown measurement. The importer cannot grant adoption or release authority. An immutable fresh private bundle retains canonical observations and recomputes the report on read; changing and rehashing a reported statistic is rejected.

Success comparisons pair each task/repeat and preserve repository clustering. A fixed PCG bootstrap and preregistered comparison count give reproducible percentile intervals. Undefined ratios are retained as undefined uncertainty rather than discarded samples. Controls and safety hard stops are checked separately. Minimum cluster count is an engineering floor, not power analysis. Wilson intervals are descriptive; the comparison correction is not advertised as one joint guarantee across every metric/split/primary/repeated analysis.

A terminal original candidate can also be evaluated in a distinct private owner. The original owner remains locked. The trusted kernel imports the original CAS capture directly; a second filesystem capture would change readonly materialization permissions, lose Git executable metadata or silently filter files. Original candidate/tree/spec/document/task-sequence/check-set/profile and claim are frozen before evaluator dispatch. The complete source metadata is compared with the original journal and its digest is embedded in the evaluator protected raw input before dispatch. Rehashing all report envelope files cannot rewrite the original source claim. No current live workspace bytes or original model are used.

Only a generated fixed fixture selects the operator's bound hidden STDIO checks. It cannot mutate the ANALYSIS candidate or repair after feedback. The hidden oracle and protected result records remain in the separate owner; each subject still follows the standard durable native lease, allocation, fencing and reconciliation protocol. Baseline and current both observe the same imported tree with fresh subject identities; all overhead/repeats remain retained. Incomplete/flaky/unowned results cannot PASS. Once fixed checks finish, a generic loop's repair wait is cancelled without another coding attempt; complete quiescent FAIL remains FAIL.

The original task's claim and independent verdict remain separate. A public-case VERIFIED candidate failing a goal-consistent hidden case is recorded as false verified/success only in the evaluator. The original source, task state and model messages are untouched. Reading a native bundle requires the separate owner's full journal/CAS integrity and validated check receipts; a copied verdict JSON or rehashed summary is insufficient.

Host owner/engine administration remains trusted. This is local kernel-produced evidence for exact operator STDIO cases, not an externally signed attestation or proof of arbitrary semantics, real model quality, sandbox release conformance, hidden-dataset preregistration or causal harness superiority. Broad safety remains UNKNOWN. Fixture tokens are not inference usage; conservative CPU allocation is not a measured invoice. Full suite runner/condition attestation, build lineage, paired continuation, localization/performance, platform/signing/license and independent pilot acceptance remain distinct work.
