# ADR 0006 — Açık store migration ve restore ile doğrulanmış yedek

Tarih: 8 Ekim 2026. Durum: 0.6.0-dev engineering profilinde uygulanmış. PRD §11, §14, §28 F20/F34/F35 ve NFR-07'nin v1→v2 dilimi. Tam P04, privacy deletion ve donanım power-loss conformance kabulü açık.

Store formatı ile task/event/reducer sürümü ayrı tutulur. Yeni store format 2 oluşturur; mevcut format 1 store normal açılışta değişmez. Eski binary daha yeni formatı reddeder. Format 2 manifest'i rastgele store kimliği, schema/reducer, sabit format DDL digest'i ve varsa migration lineage taşır. Snapshot format manifest digest'ini de bağlar. DDL digest'i bütün SQLite catalog'ının yapısal doğrulaması veya bir imza değildir.

store-migrate exclusive owner altında yürür; active task, pending/UNKNOWN effect veya retained reservation varken durur. Source ile store/backup path'leri ayrıdır. Eski biçimdeki tam CAS+SQLite yedeği oluşturulur veya aynı journal'a ait tamamlanmış yedek tekrar kullanılır. Yedek gerçekten fresh store'a restore edilir; raw input, context, check origin, candidate ve tarihsel journal/CAS closure kontrol edilir. Özel geçici doğrulama kopyası işlem sonunda kendi opened-root alanından kaldırılır. Task, model veya source effect çalıştırılmaz.

Sıra: doğrulanmış yedek → immutable intent → SQLite transaction içinde format table/lineage/user_version → committed completion marker. Intent command ID, canonical backup path/digest ve source sequence/tail ile bağlıdır. Journal/events/payloads/commands/checkpoint içerikleri yeniden yazılmaz. Sonuç aynı command ID için original receipt'tir; farklı request veya journal command ID çakışması reddedilir.

Intent yayınlanmadan hemen önce admission durur; publication'ın directory-sync hatası belirsiz olsa da yeni iş açılmaz. Commit belirsizliğinde gerçek schema tekrar okunur. Pending migration açılışı generation yükseltmez, event/checkpoint/agent/CAS admission'ını kapatır; inspect/replay/status açık kalır. Original backup ve command ID ile tekrar, committed format'ı yeniden yaratmadan completion'ı tamamlar. Bozuk/missing/karışık marker veya değişmiş pending journal fail-closed olur. Intent'i silerek recovery atlanmaz.

Store volume available-space preflight'i DB boyutunun üç katı + 32 MiB ister; DB 256 MiB profilini aşamaz. Bu, fiziksel ayrılmış control reserve veya eşzamanlı disk tüketimine karşı garanti değildir. Backup/restore 512 MiB/32.768 file limitini korur. Eski format 1 backup format 1 olarak restore edilir; yeni migration'lı format 2 backup intent+completion metadata'sını ve exact format digest'ini korur. Incomplete migration'dan yeni normal backup üretimi reddedilir; original pre-migration backup recovery kaynağıdır.

Checkpoint local digest'i yeterli sayılmaz; bütün historical checkpoint'ler journal prefix ile tekrar karşılaştırılır. DB/WAL/SHM/owner-lock regular/single-link guard'ları SQLite/lock erişiminden önce çalışır. Bunlar trusted private-directory preflight'leridir; hostile aynı kullanıcı race izolasyonu veya tam OS sandbox kanıtı değildir.

Kabul: before/after intent/SQL commit/completion sınırlarında gerçek subprocess abrupt-exit fixture'ları; reopened read-only/generation davranışı; task/global cursor, replay, checkpoint ve command dedup eşitliği; changed backup/intent, invalid format/downgrade, corrupt and rehashed checkpoint, active/unknown task ve low-space reddi; uygulama/CLI eski ve yeni full restore testi. Elektrik kesintisi/disk controller/filesystem matrisi, disk-full kernel control reserve, retention/delete/tombstone/managed-copy purge ve install/update kabulü bu ADR ile kapanmaz.
