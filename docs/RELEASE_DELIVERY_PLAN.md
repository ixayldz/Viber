# GitHub dağıtımı ve kurulum teslimi

11 Ekim 2026. Kullanıcı public GitHub indirme/kurulum akışını istedi. Yetkili üretim kapısı [PRD §25–29](../prd.md); engineering build, public preview ve kararlı ürün farklı kabul taşır. İlk üç-platform portable engineering/OIDC/public indirme kabulü tamamlandı; yeni fresh archive kurulum/kaldırma ve ayrı rapor attestation dilimi kendi exact-SHA kabulünü bekler. Aktif indirme yönergeleri [INSTALL](INSTALL.md) içindedir.

## Paket sözleşmesi

- İlk native hedefler: Windows amd64, Linux amd64, macOS arm64. Başka platform cross-build ile destek kazanmaz.
- Build immutable exact Git commit archive'ından, Go 1.27.2 ve doğrulanmış go.sum ile yapılır. SBOM/lisans envanteri her hedefin gerçek binary dependency closure union'ıdır; test/tool graph binary lisansı diye sunulmaz.
- İki build byte hash eşitliği; binary version/platform/build source identity; private per-target manifest; MIT, dependency attribution, CycloneDX SBOM, kullanım kılavuzu ve offline ilk görev fixture'ı birlikte paketlenir.
- Archive byte hash'leri, exact revision ve native smoke kabulünü taşıyan dağıtım manifest'i en son yayınlanır. Partial output complete package sayılamaz.
- GitHub Actions OIDC build provenance archive/binary hash'lerine bağlanır. Consumer repo, signer workflow, source ref ve digest'i doğrular. Yalnız indirme sayfasındaki checksum authenticity değildir. Windows Authenticode/macOS Developer ID/notarization ayrı platform signing kapsamıdır; OIDC bunlar diye gösterilmez.

## Native install/update/rollback

1. Kullanıcı doğrulanmış paketi kendi private uygulama dizinine kurar; sistem/admin PATH yazımı zorunlu değildir. Native hedef uyuşmazlığı veya unsupported architecture allocation öncesi reddedilir.
2. Sürümler ayrı dizinlerde kalır. Temp/final publication ayrı, mevcut binary/user files/store üzerinde silent overwrite yoktur. Running owner veya destination conflict explicit sonuç verir.
3. Update önce signature/manifest/platform/hash/compatibility doğrular, sonra yeni sürümü stage eder, doctor ve ilk görev smoke kabulünden sonra current pointer değişir. Başarısız stage mevcut kurulumu korur.
4. Rollback explicit seçilen daha önce doğrulanmış binary sürümüne döner; task journal/schema/privacy authority downgrade veya restore otomatik değildir. Incompatible store read-only/fail-closed kalır. Uninstall programı kaldırır, kullanıcı task/store/credentials'ını açık ayrı consent olmadan silmez.
5. Windows/macOS/Linux native CI: fresh install, reinstall/dedup, altered package/manifest, wrong platform, partial stage/process death, concurrent updater, running owner, update, rollback, uninstall ve ilk offline görev. Fixture gate kriptografik provenance veya gerçek platform kabulü diye sayılmaz.

## GitHub publication

Foundation güncel exact-SHA'da bütün platform full/vet/vulnerability/migration, Linux full race/fuzz, rootful/rootless ve native vault kabulünü ister. Kırmızı/atlanan kapılar üzerinde stable release yoktur. Yeni release workflow güven sınırı pinned action commit'leri ve minimum job permissions kullanır; PR/fork code'u release write token veya OIDC yetkisi alamaz.

Release assets Windows ZIP ve Unix tarball, checksum inventory, SBOM, lisanslar, bounded install/update/rollback yönergeleri ve build provenance içerir. Public stable tag yalnız ilgili A–D PRD test matrisi, privacy/resource/verifier/supervisor/delivery ve bağımsız pilot kapıları kapandıktan sonra yayımlanır. API kabulünün eksik kalması açıkça provider/profile kapsamını sınırlar; mühendislik veya anahtarsız dış kabul eksikleri API anahtarı diye etiketlenmez.

Engineering publication ayrı explicit `engineering-FULL_SHA` lightweight tag push'uyla başlar. `scripts/engineering-release.py` aynı revision'ın en yeni main/push core run'ında bütün 12 job SUCCESS ister; daha yeni failure varken eski successful run seçmez. Üç bounded native artifact archive'ı parsing öncesi repo/workflow/ref/source digest bağlı provenance ile doğrulanır. Archive içindeki actual native scope, compiler/platform/source identity, file inventory/bytes/types/modes ve deliberate UNVERIFIED sonucu readback edilir; binary execute edilmez. Minimum contents-write job draft yaratır, response'taki exact database ID'ye upload/readback/publication bağlar; tag endpoint'i yalnız published release için kullanılır. Bütün asset'lerin exact byte download'u ardından draft/body/asset ID/digest, current CI ve tag tekrar okunur; prerelease/latest=false yayımlanır. Partial failure draft kalır; existing release/tag overwrite veya --clobber yoktur. Recovery yalnız explicit pozitif draft ID ve aynı source/notlar/inventory/byte kabulüyle mümkündür. GitHub release CAS sağlamadığından bu kontroller repository'nin eşzamanlı yetkili değişikliğine karşı atomik garanti diye gösterilmez.

İlk [public engineering release](https://github.com/ixayldz/Viber/releases/tag/engineering-1f145f6d1062129a3b2506b1a7ab570ad0739416) mevcut: source `1f145f6`, exact 12-job native pipeline SUCCESS; gerçek CI upload, explicit-ID recovery/readback/public effect ve anonim download PASS. İlk publisher workflow'un draft/tag lookup failure'ı silinmez veya SUCCESS diye yeniden yazılmaz. Son düzeltmenin **59 publication trust / 31 portable inventory kontratı PASS**; bu fixture sayısı yeni normal POST/upload workflow'un server kabulü değildir. `97180e4` native 12-job kabulü SUCCESS, normal publisher explicit historical workflow-changing target SHA için HTTP403 ile FAILURE; son fix exact existing tag'i yeniden doğrulayıp kullanılmayan target_commitish'i kaldırır. Normal route final kabulü yeni exact SHA ister. Otomatik installer/update/rollback, OS certificate signing, bağımsız pilot ve stable acceptance ayrı açık kapsamdır.

Yeni native paket gate'i archive'ın exact inventory/type/mode/byte kontrolünden sonra fresh private sürüm dizinine gerçek archive byte'larını açar. CLI ayrı process'te PATH=EMPTY/Git undiscovered iken version/doctor/offline first task/diff çalışır. Store programdan ayrı private sibling'dedir; yalnız program dizini kaldırılınca task/authority file hash/length inventory aynı kalır ve independent exact binary ile diff yeniden okunur. Scope `FRESH_ARCHIVE_FIRST_TASK_MANUAL_UNINSTALL_ONLY`; automatic updater, farklı store-format rollback ve owner concurrency kabulü değildir. Windows frozen-source package route ve public Windows/Linux native testleri PASS; macOS ve yeni revision'ın bütün gate'leri CI'da ayrıca ölçülür.

Yeni signing job üç archive ile üç `distribution.json` raporunu **altı subject** olarak ayrı OIDC authority'de attest eder ve her birini consumer repo/workflow/ref/source digest ile doğrular. Publisher raporu parsing öncesinde attest kontrolünden geçirir; archive hash/native scope'a bağlar. Üç platform raporu `*-distribution.json` adıyla public assets'e byte'ları değişmeden eklenir; kullanıcı aynı `gh attestation verify` komutuyla raporu da doğrulayabilir. Public manifest/checksum bu altı artifact ve exact CI kaynağını gösterir; checksum tek başına authenticity değildir. Eski `1f145f6` beş-asset release'i bu yeni altı-subject veya üç-platform fresh-uninstall kabulü diye yeniden etiketlenmez.

[GitHub build attestation](https://docs.github.com/en/actions/how-tos/secure-your-work/use-artifact-attestations/use-artifact-attestations) ve [consumer verification flags](https://cli.github.com/manual/gh_attestation_verify) resmi protokol kaynaklarıdır. Kriptografik build provenance, source'un PRD'yi karşıladığına dair evaluator verdict değildir.
